# Pickaxe Memory OS Spec

Status: Future / Planned. Documentation only.

## Purpose

Memory OS preserves source context, decisions, outcomes, mistakes, rules, and company continuity so Pickaxe improves without pretending to learn autonomously.

## Core Modules

- Archive
- Learning Ledger
- Source lineage
- Decision history
- Rule registry
- Codex prompt improvements
- Daily System Improvement
- Performance Tracker

## Performance Tracker

Aliases: P&L Calendar, Trading Performance Dashboard, Learning Ledger Performance View, CEO B Performance OS.

- Owner: Archive + Learning Ledger
- Future route: `#/performance`
- Connected systems: Options Alerts, Quant Lab, Memory OS, Mission Control
- Status: Future / Planned

### Purpose

Track CEO B's private trading and research performance over time so reviewed packets, outcomes, mistakes, seasonality, streaks, drawdowns, and lessons become measurable.

### Required Views

- Year Calendar Grid
- Executive Summary
- Year-by-Year Comparison
- Top 5 Best Months
- Top 5 Worst Months
- Month Seasonality
- Streaks / Quarter Stats / Insights
- Alpha Notes
- Rule Break Tracker
- Options Contract Quality Summary
- Volatility Context Summary
- CEO B Review Compliance

### Metrics

- net P&L
- gross gains
- gross losses
- win rate
- profit factor
- expectancy
- average win
- average loss
- gain/loss ratio
- active months
- winning months
- losing months
- monthly volatility
- max drawdown
- best month
- worst month
- best trade
- worst trade
- rule breaks
- CEO B reviewed percentage

### Safety

- private analytics only
- research and education only
- no public performance claims
- no guaranteed returns
- no broker execution
- no broker account sync
- no copy-trading
- no fake live data
- no public leaderboard
- CEO B final review required

Do not implement until Options Alerts, Risk Desk, CEO B Review Gate, and Archive Outcome are stable.

## Rule Versioning

Every adopted rule should record:

- rule ID
- prior version
- trigger outcome
- evidence
- proposed change
- CEO B decision
- effective date
- affected product
- validation requirement
- rollback condition

## Non-Autonomy Rule

Memory OS stores and proposes. It does not self-modify, approve its own recommendations, create fake live agents, or bypass CEO B.
