Status: Canonical product and brand lock.
Authority: CEO B.
Scope: Public Options Alerts product language, desktop hierarchy, gate model, visual tokens, support-route roles, and future boundaries.

## 1. Product Mission

Pickaxe Capital presents one focused public product: Options Alerts Research OS. The product helps CEO B and approved teammates rank options setups, inspect evidence, see missing gates, and keep every setup blocked from external action until source, timestamp, options-chain, liquidity, risk, System Intelligence, CEO B Standard, and action-boundary requirements pass.

Product sentence:

`Rank setups. Verify evidence. Block action until every required gate passes.`

## 2. Current Product Boundary

The public runtime is static-first, vanilla HTML/CSS/JavaScript, and served from `public/` through GitHub Pages. Browser state is LocalStorage/static only. The current product state is `DEMO / Source Required`, `UNKNOWN / No market timestamp`, and `BLOCKED — NO EXTERNAL ACTION`.

No backend, live provider, broker execution, authentication, payment, subscription, alert delivery, autonomous publishing, or live market data path is active.

## 6. Canonical State Model

- `BLOCKED`: one or more hard gates are missing, unavailable, stale, invalid, or failed.
- `WATCH`: source/time/chain requirements are usable, but research conditions remain incomplete.
- `RESEARCH REVIEW`: required research gates pass for deeper internal review, still without automatic external action.
- `NO SETUP`: setup conditions fail or invalidation/no-trade conditions dominate.

Research Readiness controls review order and packet completeness. It never overrides a failed gate.

## 7. Gate Precedence

Gate precedence is:

1. Source Gate
2. Timestamp Gate
3. Options-Chain Gate
4. Spread / Liquidity Gate
5. Risk Gate
6. System Intelligence Gate
7. CEO B Standard
8. Action Boundary

Core rule: `No external action unless every required gate passes.`

## 8. CEO B Standard

CEO B is the founder-approved governance doctrine embedded into System Intelligence. Public product language should use `CEO B Standard`, `CEO B Standard: Applied`, `Founder Override Available`, `Separate Public Activation Required`, `Governance review required before production promotion`, and `No External Action` with precision. It must not present CEO B as a visible accept/decline button or public manual-approval bottleneck.

## 9. Setup Card Contract

Each setup card shows ticker, setup name, Research Readiness, System Status, Source Status, Options Quality, selected state, and one concise missing requirement. Selection must be visible by structure and accessible state, not color alone.

## 10. Selected Setup Contract

The selected setup surface shows setup identity, research bias/context, timeframe, Research Readiness, Options Quality / Contract Grade, Source State, Source Confidence where available, Risk State, System Verdict, failed gates, missing requirements, next required evidence, and action boundary.

## 11. System Verdict Contract

System Verdict must show Status, Why, Passed Gates, Failed Gates, Missing Evidence, Next Requirement, CEO B Standard, and Action Boundary. It must not resemble an order ticket.

## 12. Research Packet Role

Research Packet is the detailed thesis record: setup identity, thesis, catalyst, research conditions, available levels, invalidation, no-trade conditions, options context, contract quality, risk state, source state, missing gates, System Verdict, and research-only boundary.

## 13. Evidence Packet Role

Evidence Packet shows what is Known, Missing, Unverified, Blocked, and Required Next. It must preserve static/demo truth, no usable market timestamp, no verified options chain, no verified live provider, and no external action.

## 14. Sources Role

Sources explains Current Source State, Available Inputs, Missing Inputs, Freshness State, Why Alerts Is Blocked, and the Future Authorized Data Path. Provider activation requires separate CEO B authorization, commercial/legal clearance, server-only credentials, secure fixed-function transport, credentialed local verification, stale-data controls, and separate public-connection approval.

## 15. Rules Role

Rules explains the gate model visually and simply. Gate states are `PASS`, `MISSING`, `BLOCKED`, or `NOT EVALUATED`. Rules must explain that high readiness cannot override missing source truth and high options grade cannot override stale or missing timestamps.

## 16. Status Role

Status records the active checkpoint, hosted state, static GitHub Pages architecture, demo/source-required data state, blocked system state, route ownership, validation evidence, and absent provider/broker/auth/payment/subscription/alert-delivery systems.

## 17. Navigation Hierarchy

Primary visible navigation remains Alerts, Sources, Rules, Status, and Founder. Internal, legacy, future, and experimental routes remain available through the existing deferred/internal structure. No new route or app shell is created by this lock.

## 19. Founder Ghost Gray

Founder Ghost Gray represents restraint, executive calm, precision, and understated founder signature. It is used selectively for founder-associated accents, premium selected surfaces, signature dividers, and CEO B Standard details. It must not become the majority background or bullish/bearish/blocked semantic color.

## 20. Typography Roles

Display type is limited to product identity and major route headers. UI sans owns navigation, body, cards, and buttons. Mono/status type owns timestamps, gates, scores, status labels, and microcopy. Labels must stay readable and not rely on excessive uppercase paragraphs.

## 21. Component Rules

Components use shared spacing, panel padding, border radius, border opacity, selected state, hover/focus state, blocked state, pass state, source-required state, button hierarchy, chip hierarchy, empty state, unavailable state, demo state, and disclosure styling. Avoid duplicate page concepts, duplicate renderers, nested card clutter, and unnecessary `!important`.

## 22. Accessibility Rules

The workflow requires semantic headings, visible keyboard focus, keyboard-usable setup selection, accessible selected state, accessible disclosures, synchronized `aria-expanded`, readable contrast, no color-only meaning, reduced-motion preservation, and meaningful button labels.

## 23. Investor Readiness
