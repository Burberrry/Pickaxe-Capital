# Pickaxe Brand Simplification And Memory Hygiene

Status: Canonical docs-only governance lock.
Date: 2026-06-21.
Authority: CEO B.
Runtime authority: None.

This document simplifies naming, public structure, and repository memory without deleting the working system or authorizing runtime changes.

## 1. Executive Decision

- The public brand and project name is `Pickaxe Capital`.
- `Pickaxe Capital / AI Habitat OS` must no longer be used as the public-facing project title.
- `AI Habitat OS` remains an important internal architecture layer inside Pickaxe Capital.
- The working static application remains intact. This decision changes governance and future copy direction, not current runtime behavior.

## 2. Naming Hierarchy

| Layer | Canonical name | Use |
| --- | --- | --- |
| Public brand | `Pickaxe Capital` | Public website, company identity, primary headings, product story, domain strategy, and external references |
| Internal operating system | `AI Habitat OS` | Intelligence, agents, source verification, research workflows, memory, Archive, Learning Ledger, Staging / QA, and CEO B review |
| Symbolic command identity | `CEO B` | Masked final-review and command identity |
| Human founder identity | `Founder B` | Separately approved founder, biography, investor, and company materials |

CEO B and Founder B support one founder-led system but are not interchangeable visual or factual artifacts.

## 3. Why The Rename Matters

The combined name is too long and merges the company with its internal architecture. That weakens recall, makes the website harder to understand, and forces internal terminology into public explanations. Public users should remember one name: Pickaxe Capital. AI Habitat OS remains strategically useful, but it should support the brand rather than compete with it.

The simpler hierarchy improves homepage clarity, future domain strategy, founder identity, product credibility, navigation decisions, and the ability to explain the company in one sentence.

## 4. Public Copy Rule

Preferred public language:

- `Pickaxe Capital`
- `Pickaxe Capital Intelligence`
- `Pickaxe Capital Research OS`
- `Pickaxe Capital builds private research-intelligence systems`

Avoid as public-first wording:

- `Pickaxe Capital / AI Habitat OS`
- `AI Habitat OS platform` as the main title
- long module lists above the fold
- internal route names as hero copy
- every future module name in public copy

Public copy must distinguish current static/manual capability from future architecture and must preserve research, source, risk, and manual-review boundaries.

## 5. Internal Copy Rule

Internal documentation and operating routes may use:

- `AI Habitat OS`
- `Agent Habitat`
- `Mission Control`
- `Source Hub`
- `Archive`
- `Learning Ledger`
- `Staging / QA`

Before foregrounding internal terminology, ask whether it helps the website, brand identity, CEO B build process, source verification, product clarity, or future implementation. If it does not, demote it to supporting context or archive/reference status.

## 6. Memory Hygiene Rule

Keep memory that improves:

- website quality and public clarity;
- Pickaxe Capital and CEO B identity;
- product architecture and module boundaries;
- route ownership and active render truth;
- source verification, risk, compliance, and CEO B review;
- Codex execution discipline;
- current build status and bounded roadmap;
- useful resources and visual standards.

Do not foreground memory that is duplicate, stale, unverified, speculative, unrelated to the website, emotionally noisy, non-actionable, overloaded with future names, or unhelpful to CEO B decisions.

Memory hygiene is classification, not mass deletion. Historical records may remain available without controlling current product direction.

## 7. Memory Classification System

### KEEP / CORE

Brand name, official logo rule, CEO B and Founder B identity boundaries, route architecture, active checkpoints, locked safety rules, source-verification doctrine, current product modules, and Codex sprint discipline.

### KEEP / SUPPORTING

Module concepts, future roadmap, visual experiments, historical build notes, prompt libraries, and bounded design studies that remain useful but are not public-first.

### ARCHIVE / REFERENCE

Old phases, past sprints, completed QA detail, superseded implementation notes, and old module concepts that may help trace decisions but should not dominate current context.

### REMOVE / DO NOT USE

Duplicate wording, obsolete public names, outdated route truth, fake-live concepts, unsupported feature claims, forbidden module references, and language that weakens public clarity. Removal from active use does not authorize broad historical file deletion.

## 8. Public Website Simplification Rule

Every public page should quickly answer:

1. What is Pickaxe Capital?
2. Who is building it?
3. What does it do now?
4. Why should someone trust the process?
5. What can they do next?

Public pages should not begin with a large internal tracker, a dominant command sidebar, twenty module names, every AI concept, every future system, old sprint history, technical build logs, Staging language, or raw operating-system architecture.

## 12. Brand Language To Reduce

Reduce excessive public use of “OS,” engine names, module/plugin names, future-public-company language, repeated disclaimers, overlong command-center labels, hype, and billionaire framing. Safety language remains mandatory where relevant, but it should be organized rather than mechanically repeated.

## 13. Brand Language To Remove Or Avoid

Avoid:

- `Pickaxe Capital / AI Habitat OS` as the main public name;
- fake live data, timestamps, providers, investor proof, press, endorsements, or track record;
- “AI predicts markets,” guaranteed alerts, guaranteed profit, or “best contract to buy” language;
- broker-like instructions or premature public-company claims;
- the forbidden Pickaxe Market Vector Engine concept.
