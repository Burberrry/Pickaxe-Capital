## Company Definition

Pickaxe Capital is a founder-owned research and decision-infrastructure company. Its direction is to become a company with its own technology: proprietary workflows, source rules, research packets, risk controls, memory, performance analytics, and internal tools.

The system contains two long-term habitats:

- Market Habitat: sources, watchlists, market context, options research, risk, outcomes, and research memory.
- Life Habitat: founder health, focus, learning, business creation, content, hobbies, and lifestyle leverage.

CEO B connects both habitats as owner/operator and final decision maker. CEO B is not replaced by the system. ChatGPT helps shape strategy and prompts. Codex implements only approved, scoped tasks.

## Pickaxe Origin Thesis

The Pickaxe Capital name combines two original founder ideas:

- The ambition and disciplined hedge-fund atmosphere associated with fictional finance storytelling, including inspiration from the name Axe Capital, without copying *Billions*, its characters, storylines, trade dress, or protected intellectual property.
- The Gold Rush thesis that durable businesses often come from supplying tools, maps, infrastructure, and operating systems to the people searching for gold.

Pickaxe Capital was built from the realization that in every gold rush, most people dig blindly while durable value is often created by those who sell the tools, organize the maps, provide the infrastructure, and control the operating system. In markets, the pickaxe is not a shovel. It is source verification, volatility intelligence, risk discipline, research memory, and better decision infrastructure.

Pickaxe does not only chase market moves. It builds the tools, workflows, research systems, and intelligence infrastructure that help CEO B find, test, and preserve real edge. This is an original, founder-owned company story.

Every Pickaxe story should follow five beats:

1. The environment is noisy and fragmented.
2. CEO B needs verified context, not more raw information.

The brand should communicate disciplined ambition, proprietary technology, and compounding judgment. It must not promise returns or portray automation as a substitute for the founder.

## Build the Machine Doctrine

Pickaxe must build the system that improves the system.

```text
Idea
  -> Source Hub
  -> Research Packet
  -> Risk Desk
  -> CEO B Review
  -> Outcome
  -> Archive
  -> Learning Ledger
  -> Rule Update
  -> Better Next Packet
```

Every reviewed mistake should become one or more of:

- hard block
- checklist item
- source rule
- volatility warning
- contract-quality filter
- design improvement
- Codex prompt improvement
- Archive lesson

Every improvement is proposed, never silently applied. CEO B approves all rule and product changes. Codex implements only the approved scope. There is no fake autonomous learning, fake live agent activity, or self-modifying system.

Future Mission Control concept: `Daily System Improvement`.

| Field | Purpose |
| --- | --- |
| Yesterday's mistake | Name the observed failure without hiding it. |
| Lesson extracted | Convert the outcome into a reusable principle. |
| Rule proposed | State the smallest useful system change. |
| CEO B decision | Approve, revise, defer, or reject. |
| Hard block updated | Record whether a blocking rule changed. |
| Best source | Identify the most decision-useful source. |
| Worst source | Identify the weakest or most misleading source. |
| Next system improvement | Queue one bounded improvement. |

The doctrine is inspired by repeatable company-building systems: reduce work to first principles, document the process, measure bottlenecks, improve the machine, and reuse proven infrastructure across products. It does not copy or impersonate any individual founder.

## Pickaxe Institutional Prompt Engine

Motto: **Raw idea in. Institutional output out.**

Long form: Every rough founder thought gets upgraded into a structured prompt, tested against the Pickaxe Quality Gate, converted into a system component, and archived for compounding improvement.

### Core Loop

```text
Raw Thought
  -> Clarify Intent
  -> Upgrade Prompt
  -> Apply Institutional Quality Gate
  -> Produce Output
  -> Define Next Action
  -> Archive Lesson
  -> Improve Next Prompt
```

### Permanent Rule

When CEO B gives a rough idea, short command, messy note, screenshot, partial thought, or unfinished concept, do not answer it at the surface level. First convert the input into an institutional-grade prompt.

The upgraded prompt must identify:

1. The real objective
2. The target page, feature, agent, workflow, or decision
3. The institutional standard required
4. The user experience or operator experience
5. The data inputs needed
6. The outputs expected
7. The agents or departments involved
8. The risk, disclosure, and research boundaries
9. The build format or deliverable
10. The next execution step

### Pickaxe Institutional Quality Gate

Every upgraded prompt and output should be tested against the 20-point gate:

1. **Clarity** - Does this make Pickaxe easier to understand in 10 seconds?
2. **Trust** - Does this make Pickaxe feel more credible, disciplined, and transparent?
3. **Research Quality** - Does this improve the quality, structure, sourcing, or verification of research?
4. **Decision Quality** - Does this help CEO B make better, calmer, more evidence-based decisions?
5. **Memory** - Does this create a record the system can learn from later?
6. **Source Integrity** - Does this preserve where information came from, when it was captured, and how reliable it is?
7. **Risk Control** - Does this expose red flags, weak evidence, liquidity risk, volatility risk, or overconfidence?
8. **Human Review** - Does this keep final judgment with CEO B instead of blindly trusting automation?
9. **Research Boundary** - Does this avoid fake signals, investment-advice language, broker execution, copy-trading, and guaranteed outcome claims?
10. **User Experience** - Does this make the system easier to use, navigate, and act on?
11. **System Architecture** - Does this fit cleanly into the Pickaxe operating system instead of creating clutter?
12. **Automation Readiness** - Can this later be automated, connected to APIs, logged, or converted into a reusable workflow?
13. **Data Quality** - Does this improve data structure, tagging, filtering, scoring, or retrieval?
14. **Public-Company Discipline** - Does this support clean records, reporting, governance, disclosures, and future auditability?
15. **Investability** - Would this make Pickaxe look more serious, scalable, defensible, and institutionally prepared?
16. **Founder Leverage** - Does this multiply CEO B's judgment, speed, and execution capacity?
17. **Compounding Value** - Will this become more valuable as more sources, decisions, research notes, and outcomes are added?
18. **Simplicity** - Can this be made cleaner, more direct, or more useful with fewer moving parts?
19. **Proof** - Does this show real process, evidence, progress, or learning instead of hype?
20. **Strategic Fit** - Does this move Pickaxe closer to becoming an AI-native capital intelligence company?
